# Agentの挙動評価

CLIテストは保存・参照・競合等の正確性を検証します。ここでは原文から理解を形成し、現在の判断へ適用する挙動を別に扱います。全文一致の正解や機械テストで有用性を代替しません。

比較する条件は、個人記憶なし（none）、同じ原文検索結果だけ（raw）、その原文検索結果と理解（raw-and-understanding）です。同じモデル・設定・依頼・利用可能時点で、外部調査を無効にし、各条件を他条件の出力が見えない新しいコンテキストで実行します。実行順を固定せず記録します。検索結果は固定し、取得の成否と回答の妥当性を混同しません。共通の規約は各条件で同じものを読みます。

```sh
node evaluation/prepare.mjs evaluation/cases.json .local/evaluation/synthetic 2026-09-26T12:00:00.000Z
```

このコマンドはネットワーク・モデルを使わず、3条件のpromptと記録用runs.json、回答に見せないrubric.jsonを作ります。既存成果物を上書きしません。生成した入力を同じモデルへ個別に渡し、実際の回答・model・modelSettings・実行順を保存します。promptの期待条件を回答へ渡しません。秘密情報や個人例を外部モデルに送る権限は別途判断します。

各例のmust・avoidを参照して、検索の成功（retrieval）、理解の妥当性（interpretation）、提案の有用性（usefulness）、提案後の結果（outcome）を別々に記録します。判定は満たした条件、違反、根拠箇所、未確認事項を残します。記憶なし条件で個人原文がないため答えられないことを、無条件の失敗にしません。理解条件の追加情報量による影響も含むため、理解の有効性と検索品質の因果をこの比較だけで断定しません。

合成例は回答・発想・計画・自己理解・レビューに加え、不足・訂正・帰属・再引用を扱います。人物像・用途・個人の基準を固定しません。実例は許可されたローカル記録から原文・版・行を確認してGit管理外に置きます。新しい評価依頼を原文から構成する場合は、実際の本人発言や実施済み相談とは扱いません。実際の訂正・提案後の結果・本人評価が見つからなければ未収集とします。合成例で補って実例と称しません。
